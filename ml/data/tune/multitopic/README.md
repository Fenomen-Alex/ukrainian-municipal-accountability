# Multi-topic augmentation set (v2)

Files generated by `ml/tune/build_multitopic.py` (seed 42; final build =
attempt-10 recipe, `n_note_target=0`):

| file                  | contents                                              |
|----------------------|-------------------------------------------------------|
| `real_annotations.json` | hand-curated decompositions (verbatim issue substrings of multi-kind complaints) |
| `train.jsonl`        | 979 chat-format training examples, each with 2 topics |
| `eval.jsonl`         | 85 held-out multi-topic examples (2 real, 83 synthetic) — **never trained on** |
| `provenance.jsonl`   | audit trail: synthetic flag, source uids, kinds, domains, n_topics, shape flag |
| `meta.json`          | build stats + leakage report                          |
| `results/lora.json`  | latest multitopic-suite eval for the final v2 model   |

## Provenance rules

- Every example's target topics are the union of *weak, deterministic* labels
  derived from real source text. Nothing is invented.
- **Real** (`synthetic: false`) — a complaint the portal registered under >=2
  `kind` values; the human annotation pins verbatim issue substrings to those
  kinds. Builder re-locates every substring in the source content or errors.
- **Synthetic** (`synthetic: true`) — shapes built from verified train-only
  content, flagged in provenance with source uids preserved:
  - `generic` (420): two single-topic train complaints from *different* domains
    joined into one message.
  - `same_street` (160): two issues sharing a street/address ("по вул. X…
    а також…").
  - `compact` (140): "По street: issue A, а також issue B" prefix form.
  - `registry` (160): faithful registry boilerplate around two issues.
  - `smoke_clone` (160, flag `smoke_clone`): two short clean clauses joined by
    "а також/через що" — closest synthetic register to the smoke suite.
- Ratio/final stream share is tuned in `ml/tune/build_v2.py` so the model still
  sees a single-topic majority in v2 (multi share ≈ 0.37).

## Leakage control

All component content is from the **train** split only. `meta.json` reports the
frozen-benchmark overlap check per example; both lists are empty. The v2 train set
is assembled in `ml/tune/build_v2.py` from these files + frozen v1 train.
