# Reproducibility

This repository keeps only **deterministic build code, documentation, schemas, manifests, and hashes** in Git. The **source-derived and generated training corpora** are **not distributed** in the public repository. They are reproducible from the official source using the deterministic pipeline described here.

## Official source

- **Dataset**: `https://data.kr-rada.gov.ua/dataset/1770a320-880f-4cd6-9840-78b9e8d93553`
- **Dataset ID**: `9109c3a3-980f-45d0-a83e-b60f87d583d4`
- **Resource ID**: `ddf7ffe9-d8e0-4646-93b2-b10d0b4bfe63`
- **Publisher**: Executive Committee of the Kropyvnytskyi City Council
- **Licence**: CC BY 4.0 International (attribution required)
- **Resource type**: `appeals.csv` (mutable). Historical snapshot `appeals_2026-08-01.csv` is not currently available; no source checksum is known.

## What is reproducible

Using the official resource and the deterministic builders in `ml/tune/` you can regenerate:
- `ml/data/train.jsonl`, `ml/data/validation.jsonl`, `ml/data/test.jsonl`
- `ml/data/tune/v2/train.jsonl`, `ml/data/tune/v2/validation.jsonl`, `ml/data/tune/v2/test.jsonl`
- `ml/data/tune/multitopic/train.jsonl`, `ml/data/tune/multitopic/eval.jsonl`
- `ml/data/tune/v3/treatment/train.jsonl`, `ml/data/tune/v3/treatment/validation.jsonl`, `ml/data/tune/v3/treatment/test.jsonl`

All steps are deterministic (fixed seeds, stable ordering). The exact row counts and PII indicators for the current HEAD are recorded in `ml/data/tune/public_data_manifest.json` (regenerated by `ml/tune/audit_public_data.py`).

## How to rebuild (authorised users)

1. Obtain the official `appeals.csv` from the source above and place it in the expected location used by the builders (consult `ml/tune/build_dataset.py` and related scripts). 
2. Run the build sequence in order (as documented in `ml/tune/MODEL_EXPERIMENTS.md` and `ml/tune/FINAL_STATUS.md`): `build_dataset.py`, `build_v2.py`, `build_multitopic.py`, `build_v3.py`, `build_v3_2.py` (or the exact commands used historically). 
3. Verify with `ml/tune/audit_public_data.py --check` and run tests: `pytest ml/tests` (corpus-dependent tests will run when corpora are present).
4. Model artifacts are independent of source text; see `ml/tune/artifact_sha256.json` and verification scripts in `ml/tune/`.

## Notes on privacy and boundaries

- Contact details are redacted by the pipeline (`ml/cleaner.py`). The auditor flags phone-like/email-like occurrences for transparency; presence does not imply unredacted PII in distributed artifacts.
- Small reviewed exceptions containing complaint-derived text remain tracked deliberately (e.g. `ml/data/gold/annotation_set.jsonl`, `ml/data/tune/eval_v3/cases.jsonl`) with justifications in `ml/tune/public_data_policy.py`. 
- The public Git history still contains historical copies of corpus files (see `PUBLIC_DATA_HISTORY.md`). `git rm` on current HEAD does not remove them.
